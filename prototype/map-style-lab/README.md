# Wemaps — Violet Night Map Style Lab

A local browser-based playground for tuning the Wemaps map appearance before implementing the style in Android.

## What it does

- Loads the original OpenFreeMap Liberty vector style, then recolors its background, land, water, roads, buildings, and labels with the custom Violet Night palette. The provider style is the data/rendering base; Violet Night is the visual overlay.
- Applies the Violet Night palette to the actual map layers.
- Lets you adjust land, water, beach, woodland, road hierarchy, road thickness, building colors, 3D opacity, camera pitch, and zoom.
- Updates the map as controls change.
- Saves palette and camera settings in the current browser's local storage.
- Exports the currently loaded and modified map as a MapLibre Style JSON file.
- Imports a MapLibre Style JSON file for further experimentation.

The prototype is a style editor, not the Android app and not an offline map package.

## Windows quick start

1. Install Python 3 if it is not already installed: https://www.python.org/downloads/windows/
2. Download the repository or check out the branch containing this prototype.
3. Open the prototype/map-style-lab folder.
4. Double-click run-windows.bat.
5. Your browser should open at http://127.0.0.1:8765/.

If that port is busy, the launcher automatically tries ports up to 8785. Keep the console window open while using the lab. Press Ctrl+C in that window to stop it.

No pip packages, Node.js, npm, build tools, or project server are required.

## Internet connection

The small Python server only serves the files on your own PC and binds to 127.0.0.1. It does not expose the preview to your local network.

The browser still needs an internet connection to load:

- MapLibre GL JS from the unpkg CDN.
- Vector tiles, style metadata, glyphs, and sprites from OpenFreeMap.

The initial map center is a neutral sample view in central Berlin. Drag the map to inspect other places. The local style controls work on the client and do not upload your palette to a Wemaps server.

## Editing the style

Use the color pickers to adjust the Violet Night palette. The map is restyled live. The left settings panel scrolls independently on desktop.

- Road hierarchy: each road class gets a separate dark Violet Night color, with bright lane markings at close zoom. The vector basemap provides the full road network. At close zoom, the prototype also requests raw OSM ways carrying `width`, `width:carriageway`, or `width:effective`, then draws a geographic-width polygon in metres. Those polygons use explicit OSM width tags only; they are not synthesized from road class.
- 3D buildings: brighter extrusion color, footprint outline, and opacity. Extrusion uses the tile's mapped render_height / height values without artificial height exaggeration.
- Camera: pitch and zoom sliders, plus quick 2D/3D buttons. The default 3D pitch is 73°. 2D/3D transitions use a longer eased camera animation; building extrusions fade in and out with the camera. When the visible map width exceeds 5 km, the prototype automatically transitions to a flat 2D view and restores the selected 3D pitch when zoomed in.
- Presets: Violet Night, Deep Purple, and Neon Violet.
- Export: downloads wemaps-violet-night.style.json.
- Import: loads a previously exported MapLibre Style JSON.

The exported style retains its underlying vector source, glyph, sprite, tile URLs, and custom layer definitions. It is a style document, not a self-contained map download. It still needs network access and remains subject to the provider's terms and attribution requirements. The five small woodland/orchard texture images are generated by the prototype at runtime and are not embedded in the JSON; a production Android renderer must register images with the same IDs before loading the style.

## Known limitations

- The prototype uses a third-party style/data service. Initial loading speed still depends on the network, CDN, and tile provider. The map canvas remains dark while loading, and interrupted style/vector responses trigger up to two automatic reload attempts; persistent Content-Length/body mismatches still require a working network path. Camera easing, label fading, a deeper tile cache, progressive tile loading, and WebGL antialiasing are enabled to favor smoother movement. Extra detail layers are gated by zoom to avoid drawing them at distant scales. Availability, coverage, update frequency, and terms are controlled by that provider.
- 3D building quality depends on the building data and height attributes available in each area.
- The extrusion color is shared by roof and walls; MapLibre's vertical gradient shades the sides. The footprint outline is controlled separately. OpenMapTiles exposes render_height and render_min_height, which may be derived from explicit height or building levels; no arbitrary 9 m fallback or height multiplier is applied. Buildings without usable height data are not given an invented height.
- Exact-width overlays are built only from OSM `width:carriageway`, `width`, or `width:effective` tags returned by Overpass. A road without one of these tags stays on the vector-map fallback; its width is an estimate from road class, not a measured value. OSM `lanes` tags are used to position lane dividers, but a lane count is not treated as a measured carriageway width. The standard OpenMapTiles transportation vector schema does not expose these raw width and lane tags, which is why the close-zoom Overpass request is separate. Bridge segments receive a raised-deck/shadow treatment; motorway ramps receive a separate highlight.
- Camera/junction data and raw road geometry are fetched through two independent Overpass requests and kept in separate GeoJSON sources, so a slow road-width response does not block camera markers. Camera points are requested from zoom 13.5; ways with width/lane tags are requested only at zoom 16.5 and closer. Each request is debounced, cached for five minutes by viewport, and aborted after 12 seconds. A marker shows a direction cone only when OSM includes a numeric or compass direction. Coverage depends on OSM mapping and Overpass availability; motorway ramps and bridges are styled from OpenMapTiles transportation attributes.
- Woodland polygons receive tiny repeating tree-canopy symbols only at close zoom. If a richer tile source exposes leaf_type, conifer and broadleaf patterns can be selected separately. The standard OpenMapTiles landcover schema has class and subclass but does not guarantee species or individual tree points, so the generic pattern is not a claim about the exact trees in that forest.
- Beach and sand subclasses receive a dark sand-gold color.
- This prototype does not implement route calculation, GPS tracking, speed-limit alerts, search, or weather.
- It does not download offline areas.

## Technology

- MapLibre GL JS 6.16.0, pinned in the HTML.
- OpenFreeMap Liberty base style with the custom Violet Night overlay.
- Python 3 standard library for the local static HTTP server.

MapLibre GL JS is a browser renderer from the MapLibre project. Its official repository and releases are available at https://github.com/maplibre/maplibre-gl-js.
